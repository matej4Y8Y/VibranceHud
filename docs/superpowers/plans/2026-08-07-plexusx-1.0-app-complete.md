# PlexusX 1.0 — Finished Application Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Take PlexusX from "mostly built" to a finished, sellable 1.0 desktop application — every control in the app's own visual language, every legal blocker cleared, every feature placed where a user would look for it, and a rulebook enforced by tests so the same classes of defect cannot come back.

**Architecture:** Rules first, then compliance with those rules. Phase 0 writes an executable UI/system contract — tests that fail the build when a stock Win32 control, a hardcoded colour, a culture-dependent number, or an unreachable page appears. Every later phase is then verified by that contract rather than by eye. Work proceeds page-by-page and tool-by-tool, each task ending in a green suite and a rendered screenshot.

**Tech Stack:** C#/.NET 8, WinForms, xUnit, self-contained win-x64 single-file publish, Inno Setup (`VibranceHud.iss`), GDI+ owner-drawn controls.

**Out of scope (this is part 1/2):** website, backend, payment webhooks, merchant-of-record integration, code-signing certificate purchase. Part 2/2 covers those. Where the app needs to *point at* one of those (a privacy URL, a checkout link), use the constant already in `AppInfo` and leave the destination for part 2.

## Global Constraints

These are project-wide. **Every task's requirements implicitly include this section.** Phase 0 turns each one into a test; after Phase 0 a violation is a build failure, not a matter of opinion.

### UI contract

- **U1 — No stock Win32 controls in shipping UI.** `Button`, `TextBox`, `ComboBox`, `CheckBox`, `RadioButton`, `LinkLabel`, `NumericUpDown`, `TrackBar`, `GroupBox`, `ListBox`, `TabControl` must not be constructed anywhere outside `Controls/`. Use `GlassButton`, `GlassTextBox`, `GlassDropdown`, `ToggleSwitch`, `ChipButton`, `FlatSlider`. `Label` and `Panel` are allowed (they have no Win32 chrome). `GlassTextBox` hosts a real `TextBox` internally — that single exception lives in `Controls/GlassTextBox.cs` and nowhere else.
- **U2 — No hardcoded colours.** Every colour comes from `Theme.*`. `Color.FromArgb` is allowed only for alpha-blending a `Theme` colour, or inside `Controls/` and `Theming/` for painting primitives. No `SystemColors.*` anywhere.
- **U3 — Fonts come from `Design/Fonts`.** No `new Font(Theme.FontFamily, …)` outside `Design/`. The one permitted exception is an explicit monospace face (`"Consolas"`) for codes and hex values.
- **U4 — Spacing comes from `Design/Tokens`.** No new magic numbers for gutters and gaps in page layout.
- **U5 — Nothing clipped, nothing overlapping.** Every label is at least as large as the text it renders, measured with slack (`TextRenderer.MeasureText(…, WordBreak).Height + 6`), because `MeasureText` and `Label` do not lay out identically. Every child fits inside its own card.
- **U6 — Every page can reach its own content.** `AutoScroll` plus a real `AutoScrollMinSize` via `FitScrollToContent()`. The mouse wheel works with the cursor over any descendant.
- **U7 — Every interactive control is keyboard-reachable and announced.** `TabStop = true`, `AccessibleRole` set, `AccessibleName` tracks `Text`, and a visible focus ring. A control that handles arrow keys must claim them in `IsInputKey` or WinForms eats them as dialog navigation.
- **U8 — Every control paints in every state.** Normal, hover, pressed, focused, **disabled**, at 1×1 and 2000×40, in all four themes, without throwing. A disabled control must look disabled.
- **U9 — All user-visible numbers use `CultureInfo.InvariantCulture`.** The UI is English; a Czech Windows must not render `1,00`.
- **U10 — No dead affordance.** A control that is shown must do something. Unset state says "Not set", never `(none)` or `0x0`.
- **U11 — Dialogs are `GlassDialog` or handle Enter/Escape by hand.** `GlassButton` is not an `IButtonControl`, so `AcceptButton`/`CancelButton` silently do nothing.
- **U12 — No mojibake.** No `â€`, `Ã`, `Â` byte sequences in any source file.

### System contract

- **S1 — No anti-cheat risk surface beyond what already ships.** No injection, no memory reads/writes, no new handles opened into a game process. This plan adds none. (`RustSystemBoost.RaisePriorityWhenRustStarts` already exists and stays as-is; it is not to be extended.)
- **S2 — No raw exception dialogs.** Every unhandled path reaches the friendly crash dialog and writes a crash log.
- **S3 — Settings must never be silently lost.** Any new persisted field needs a round-trip test through `SettingsStore`.
- **S4 — No blocking the UI thread.** Anything touching disk, network, or the display driver on a user gesture must not freeze the window.
- **S5 — Honest claims only.** No feature text that promises something the code does not do. Where a capability depends on the machine, the capability probe decides the wording.

### Process contract

- **P1 — TDD.** Failing test first, then the minimal implementation, then green.
- **P2 — Full suite green before every commit.** `dotnet test tests/VibranceHud.Tests/VibranceHud.Tests.csproj`. Current baseline: **1204 passing, 4 skipped**. The count only goes up.
- **P3 — Visual changes are verified by rendering, not by reasoning.** Use the off-screen `Form` + `DrawToBitmap` harness (Task 0.5). A change nobody looked at is not done.
- **P4 — Commit per task**, message in the established style: what changed, and *why it was wrong before*.
- **P5 — Never claim done without evidence.** Paste the test line. If something is skipped or blocked, say so.

### Decisions reserved for the user — do NOT guess, do NOT block

If a task hits one of these, **implement the safe default, leave a note in `docs/OVERNIGHT-LOG.md`, and continue**:

- Pricing numbers, plan names, trial length changes.
- The company/legal entity name and address in legal documents → use the placeholder `[[LEGAL_ENTITY]]` and log it.
- Any destination URL not already in `AppInfo`.
- Removing or disabling an existing user-facing feature.
- Anything that would change what a paying user already has.

```csharp
using System;
using System.Collections.Generic;
using System.IO;
using System.Linq;
using System.Text.RegularExpressions;
using Xunit;

namespace VibranceHud.Tests
{
    /// <summary>
    /// The design rules, as tests.
    ///
    /// Written because "this doesn't match the theme" kept arriving as a message rather than
    /// as a build failure. A stock Win32 control cannot be themed - a flat Button keeps square
    /// corners and the system focus rectangle - so the only reliable rule is that it must not
    /// be constructed at all outside the one place that wraps it.
    /// </summary>
    public sealed class UiContractTests
    {
        /// <summary>Repo root, found by walking up from the test binary until the csproj is seen.</summary>
        internal static string RepoRoot()
        {
            var dir = new DirectoryInfo(AppContext.BaseDirectory);
            while (dir != null && !File.Exists(Path.Combine(dir.FullName, "VibranceHud.csproj")))
                dir = dir.Parent;
            Assert.True(dir != null, "could not find the repo root from " + AppContext.BaseDirectory);
            return dir!.FullName;
        }

        /// <summary>Every source file that ships to a user. Tests and build output excluded.</summary>
        internal static IEnumerable<(string Path, string Text)> ShippingSources()
        {
            string root = RepoRoot();
            foreach (var file in Directory.EnumerateFiles(root, "*.cs", SearchOption.AllDirectories))
            {
                string rel = Path.GetRelativePath(root, file).Replace('\\', '/');
                if (rel.StartsWith("tests/") || rel.Contains("/bin/") || rel.Contains("/obj/")
                    || rel.StartsWith("bin/") || rel.StartsWith("obj/") || rel.StartsWith("docs/"))
                    continue;
                yield return (rel, File.ReadAllText(file));
            }
        }

        /// <summary>The controls that carry Win32 chrome the app cannot paint over.</summary>
        private static readonly string[] Banned =
        {
            "Button", "TextBox", "ComboBox", "CheckBox", "RadioButton",
            "LinkLabel", "NumericUpDown", "TrackBar", "GroupBox", "ListBox", "TabControl",
        };

        /// <summary>Files allowed to touch them: the wrappers themselves.</summary>
        private static bool IsWrapper(string rel) =>
            rel.StartsWith("Controls/") || rel == "NavButton.cs" || rel == "SwatchButton.cs";

        [Fact]
        public void NoStockWin32ControlIsConstructedOutsideTheWrappers()
        {
            var offences = new List<string>();

            foreach (var (rel, text) in ShippingSources())
            {
                if (IsWrapper(rel)) continue;

                foreach (var control in Banned)
                {
                    // "new Button {" / "new Button(" - but not "new GlassButton" or "new ButtonX".
                    var rx = new Regex(@"(?<![\w.])new\s+" + control + @"\s*[({]");
                    foreach (Match m in rx.Matches(text))
                    {
                        int line = text.Take(m.Index).Count(c => c == '\n') + 1;
                        offences.Add($"{rel}:{line} constructs a stock {control}");
                    }
                }
            }

            Assert.True(offences.Count == 0,
                "Stock Win32 controls cannot be themed - use the Glass* equivalent:\n  "
                + string.Join("\n  ", offences));
        }
    }
}
```

### Task 0.5: Promote the render harness from throwaway to permanent

**Files:**
- Create: `tests/VibranceHud.Tests/RenderHarness.cs`

**Interfaces:**
- Produces: `RenderHarness.ShootAllPages(string outputDirectory)` — renders all 8 shell pages to `<name>.png`. `RenderHarness.Shoot(Control page, string path)` for a single control. Both run on an STA thread internally.

**Why this is a task and not a throwaway:** it has already been rewritten three times in one session. A page renders blank via `DrawToBitmap` unless it is parented to a **shown** `Form` — native controls only answer `WM_PRINT` once genuinely realised. That knowledge belongs in a file, not in a chat.

- [ ] **Step 1: Write the harness**

```csharp
using System;
using System.Collections.Generic;
using System.Drawing;
using System.IO;
using System.Threading;
using System.Windows.Forms;
using VibranceHud.Crosshair;
using VibranceHud.Games;
using VibranceHud.License;
using VibranceHud.Pages;

namespace VibranceHud.Tests
{
    /// <summary>
    /// Renders real pages to PNG so a visual change can be looked at.
    ///
    /// Two things here are not obvious and were each rediscovered the hard way:
    ///   - DrawToBitmap sends WM_PRINT, which a control with no handle cannot answer. A
    ///     TextBox captures as empty space unless the page is parented to a Form that has
    ///     actually been shown - CreateControl() alone is not enough.
    ///   - Showing a window needs STA, and the xUnit thread is not.
    /// The Form is parked at -4000,-4000 so nothing appears on the user's screen.
    /// </summary>
    internal static class RenderHarness
    {
        internal static readonly string[] PageNames =
        {
            "Display", "Monitor", "Crosshair", "Settings",
            "FpsTweaks", "Account", "Keybinds", "GamesHub",
        };

        internal static void ShootAllPages(string outputDirectory)
        {
            OnSta(() =>
            {
                Directory.CreateDirectory(outputDirectory);
                foreach (var name in PageNames)
                {
                    var scratch = Path.Combine(Path.GetTempPath(), "PxShot_" + Guid.NewGuid().ToString("N"));
                    Directory.CreateDirectory(scratch);
                    using var page = BuildPage(name, scratch);
                    ShootShown(page, Path.Combine(outputDirectory, name + ".png"));
                    try { Directory.Delete(scratch, true); } catch { }
                }
            });
        }

        internal static void Shoot(Func<Control> make, string path) =>
            OnSta(() => { using var c = make(); ShootShown(c, path); });

        private static void ShootShown(Control content, string path)
        {
            content.Size = new Size(900, 760);
            content.CreateControl();
            foreach (var c in Descendants(content)) c.CreateControl();

            using var host = new Form
            {
                FormBorderStyle = FormBorderStyle.None,
                ShowInTaskbar = false,
                StartPosition = FormStartPosition.Manual,
                Location = new Point(-4000, -4000),
                Size = new Size(900, 760),
                BackColor = Theme.Background,
            };
            host.Controls.Add(content);
            host.Show();
            Application.DoEvents();

            using (var bmp = new Bitmap(content.Width, content.Height))
            {
                content.DrawToBitmap(bmp, new Rectangle(0, 0, content.Width, content.Height));
                bmp.Save(path);
            }

            host.Controls.Remove(content);
            host.Close();
        }

        private static GlowPage BuildPage(string name, string scratch)
        {
            Theme.Apply("Violet");
            var settings = new AppSettings();
            var store = new SettingsStore(scratch);
            var selection = new GameSelection(settings, store);

            return name switch
            {
                "Display" => new VibrancePage(
                    new VibranceEngine(new StubController(), new StubOverlay(), new StubGamma()), settings, store),
                "Monitor" => new MonitorPage(settings, store, selection),
                "Crosshair" => new CrosshairPage(settings, store, new CrosshairService()),
                "Settings" => new SettingsPage(settings, store, _ => { }, _ => { }),
                "FpsTweaks" => new FpsTweaksPage(new SystemTweaks.SystemTweakService()),
                "Account" => new AccountPage(new LicenseService(scratch)),
                "Keybinds" => new KeybindsPage(settings, store, selection),
                _ => new GamesHubPage(_ => { }, _ => { }),
            };
        }

        private static void OnSta(Action body)
        {
            Exception? failure = null;
            var t = new Thread(() => { try { body(); } catch (Exception ex) { failure = ex; } });
            t.SetApartmentState(ApartmentState.STA);
            t.Start();
            t.Join();
            if (failure != null) throw failure;
        }

        private static IEnumerable<Control> Descendants(Control root)
        {
            foreach (Control child in root.Controls)
            {
                yield return child;
                foreach (var nested in Descendants(child)) yield return nested;
            }
        }

        private sealed class StubController : IVibranceController
        {
            public int CurrentLevel { get; set; } = 50;
            public int DefaultLevel => 50;
            public bool IsAvailable => true;
            public void SetLevel(int level) => CurrentLevel = level;
        }

        private sealed class StubOverlay : ISaturationOverlay
        {
            public void Apply(float[] matrix) { }
            public void Clear() { }
        }

        private sealed class StubGamma : IGammaRamp
        {
            public bool IsAvailable => true;
            public void Apply(ushort[] ramp) { }
            public void Reset() { }
        }
    }
}
```

## Execution order and overnight pacing

Strict order — later phases assume earlier guarantees:

1. **Phase 0** (0.1 → 0.6). ~6 tasks. Everything downstream depends on these.
2. **Phase 1** (1.1 → 1.5). The worklist is generated by 0.1, so it cannot be guessed at now.
3. **Phase 2** (2.1 → 2.3). Independent of Phase 1 — if Phase 1 stalls on something, start Phase 2 rather than idling.
4. **Phase 3** (3.1 → 3.4). Largest and least predictable. 3.1 is a deliverable even if 3.2–3.4 do not all land.
5. **Phase 4** (4.1 → 4.3). Must be last.

**If time runs short, cut from Phase 3.4 upward.** Never cut Phase 0 (the rules stop the problem recurring) or Phase 2 (legal blockers).

**Efficiency rules for a long unattended run:**
- Re-read a file only when the last edit to it was not yours.
- Run filtered tests during a task, the full suite only before a commit.
- Render pages in one batch per phase, not per task.
- Prefer editing a shared helper over N call sites — the `FlatButton` change fixed 40 buttons in one edit.
- Never spawn subagents for this work; each one re-derives context already held.
