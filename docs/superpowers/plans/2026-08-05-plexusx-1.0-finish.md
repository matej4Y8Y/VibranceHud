# PlexusX 1.0 Finish — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Take PlexusX from "works but reads as amateur" to a polished product that sells itself, by fixing the shell, adding colour depth worth sharing, and building the sharing loop into the app.

**Architecture:** Four dependency-ordered phases plus a growth phase. Design tokens land first because DPI-correct layout depends on them, and every later task consumes them. Advanced colour is built on the gamma-ramp path (a 3×256 per-channel LUT already wired into `VibranceEngine` but carrying only one power curve) — pure maths, tested without a display. Growth mechanics are all local: no server, no account, no network dependency.

**Tech Stack:** C# / .NET 8 / WinForms, xUnit, GDI+ owner-drawn controls, Win32 interop (`SetDeviceGammaRamp`, `WM_NCHITTEST`), Magnification API.

## Global Constraints

- Target framework: `net8.0-windows`. Self-contained `win-x64`, `PublishSingleFile=true`, `EnableCompressionInSingleFile=false`. Do not change these.
- Do not add NuGet packages. Every task here is implementable with the existing dependency set.
- The existing 841 tests must stay green after every task. A test that needs changing signals a deliberate behaviour change — call it out in the commit message.
- Test command: `dotnet test tests/VibranceHud.Tests/VibranceHud.Tests.csproj --nologo`
- Build command: `dotnet build VibranceHud.csproj --nologo`
- No injection, no memory writes, no process manipulation of any game. This is a hard product line (`docs/ROADMAP.md`).
- Every colour control must be reproducible from a share code. A control that cannot be encoded does not ship.
- Neutral values must produce a mathematically exact identity transform, so an untouched section is provably a no-op.
- Branch: `feat/1.0-finish`. Commit after every task.

`Design/Tokens.cs`:

```csharp
using System;

namespace VibranceHud.Design
{
    /// <summary>
    /// The one place sizes come from.
    ///
    /// Every page used to invent its own margins (28 here, 24 there, then a -4 nudge to
    /// line something up). That is why the UI reads as almost-aligned rather than aligned.
    /// These steps are the only spacing values allowed in new layout code.
    ///
    /// Values are LOGICAL pixels at 96 DPI. Run them through <see cref="Scale"/> before
    /// handing them to any control, so the same layout code is correct at 100% and 200%.
    /// </summary>
    public static class Tokens
    {
        public const int BaseDpi = 96;

        // Geometric-ish spacing scale. Nothing between these steps is permitted.
        public const int XS = 4;
        public const int S = 8;
        public const int M = 12;
        public const int L = 16;
        public const int XL = 24;
        public const int XXL = 32;
        public const int XXXL = 48;

        /// <summary>Live DPI, set by the window on creation and on every DPI change.</summary>
        public static int Dpi { get; set; } = BaseDpi;

        /// <summary>Convert logical pixels to device pixels at the current DPI.</summary>
        public static int Scale(int logical) => ScaleAt(Dpi, logical);

        /// <summary>DPI-explicit form, so the maths is testable without a display.</summary>
        public static int ScaleAt(int dpi, int logical)
        {
            if (logical == 0) return 0;
            int scaled = (int)Math.Round(logical * (dpi / (double)BaseDpi), MidpointRounding.AwayFromZero);
            // A 1px hairline must never round away to nothing - that is how borders vanish.
            return logical > 0 ? Math.Max(1, scaled) : Math.Min(-1, scaled);
        }

        public static float ScaleF(float logical) => logical * (Dpi / (float)BaseDpi);
    }
}
```

`Design/Fonts.cs`:

```csharp
using System.Drawing;

namespace VibranceHud.Design
{
    /// <summary>Named type roles, cached.</summary>
    public enum FontRole { Display, Title, Heading, Body, Label, Caption, Micro }

    /// <summary>
    /// Seven roles, replacing twelve ad-hoc sizes across 98 call sites.
    ///
    /// Cached deliberately: NavButton and GameCard used to build a Font inside OnPaint, and
    /// the animation timer invalidates the nav 30x a second across nine buttons. That is
    /// roughly 270 font objects allocated per second to draw text that never changes.
    ///
    /// Call <see cref="Rebuild"/> after a DPI change so sizes follow the new scale.
    /// </summary>
    public static class Fonts
    {
        private static Font? _display, _title, _heading, _body, _label, _caption, _micro;
        private static Font? _bodyBold, _labelBold, _captionBold, _microBold;

        public static Font Display => _display ??= Make(20f, FontStyle.Bold);
        public static Font Title => _title ??= Make(15f, FontStyle.Bold);
        public static Font Heading => _heading ??= Make(11.5f, FontStyle.Bold);
        public static Font Body => _body ??= Make(9.5f);
        public static Font Label => _label ??= Make(9f);
        public static Font Caption => _caption ??= Make(8.5f);
        public static Font Micro => _micro ??= Make(7.5f, FontStyle.Bold);

        public static Font BodyBold => _bodyBold ??= Make(9.5f, FontStyle.Bold);
        public static Font LabelBold => _labelBold ??= Make(9f, FontStyle.Bold);
        public static Font CaptionBold => _captionBold ??= Make(8.5f, FontStyle.Bold);
        public static Font MicroBold => _microBold ??= Make(7.5f, FontStyle.Bold);

        private static Font Make(float size, FontStyle style = FontStyle.Regular)
            => new(Theme.FontFamily, size, style);

        /// <summary>Drop every cached font so the next access rebuilds at the current DPI
        /// or font family. Safe to call repeatedly.</summary>
        public static void Rebuild()
        {
            foreach (var f in new[] { _display, _title, _heading, _body, _label, _caption,
                                      _micro, _bodyBold, _labelBold, _captionBold, _microBold })
                f?.Dispose();

            _display = _title = _heading = _body = _label = _caption = _micro = null;
            _bodyBold = _labelBold = _captionBold = _microBold = null;
        }
    }
}
```

```csharp
/// <summary>
/// Follow the monitor the window is on.
///
/// With PerMonitorV2 Windows sends this when the window moves between displays with
/// different scale factors, and hands us the rectangle it wants us to occupy. Taking
/// that rectangle verbatim is what keeps the window the same physical size as it
/// crosses the boundary; computing our own would make it jump.

protected override void OnDpiChanged(DpiChangedEventArgs e)
{
    base.OnDpiChanged(e);
    Design.Tokens.Dpi = e.DeviceDpiNew;
    Design.Fonts.Rebuild();
    RelayoutForDpi();

    Invalidate(true);
}
```

```csharp
public enum BorderHit
{
    None, Left, Right, Top, Bottom,
    TopLeft, TopRight, BottomLeft, BottomRight
}
```

```csharp
/// <summary>
/// Which resize border a client point falls in, if any.
///
/// Pure geometry so it can be tested without a window. Corners are checked before
/// edges because a corner point satisfies two edge tests and the diagonal cursor is
/// the one the user wants there.
/// </summary>
public static BorderHit HitTestBorder(Point p, Size size, int grip)
{
    bool left = p.X <= grip, right = p.X >= size.Width - grip;
    bool top = p.Y <= grip, bottom = p.Y >= size.Height - grip;

    if (top && left) return BorderHit.TopLeft;
    if (top && right) return BorderHit.TopRight;
    if (bottom && left) return BorderHit.BottomLeft;
    if (bottom && right) return BorderHit.BottomRight;
    if (left) return BorderHit.Left;
    if (right) return BorderHit.Right;
    if (top) return BorderHit.Top;
    if (bottom) return BorderHit.Bottom;
    return BorderHit.None;
}
```

```csharp
{
    if (m.Msg == SingleInstance.ShowWindowMessage && SingleInstance.ShowWindowMessage != 0)
        ShowAndFocus();

    // Borderless windows get no resize border from Windows, so we report one ourselves.
    // Every page in this app already carries Anchor flags for a resize that, until now,
    // could never happen - MinimumSize was set and there was no way to reach it.
    if (m.Msg == WM_NCHITTEST && WindowState == FormWindowState.Normal)
    {
        var screen = new Point(m.LParam.ToInt32() & 0xFFFF, (m.LParam.ToInt32() >> 16) & 0xFFFF);
        var client = PointToClient(screen);
        int grip = Design.Tokens.Scale(6);

        int hit = HitTestBorder(client, ClientSize, grip) switch
        {

            BorderHit.Right => HTRIGHT,
            BorderHit.Top => HTTOP,
            BorderHit.Bottom => HTBOTTOM,
            BorderHit.TopLeft => HTTOPLEFT,
            BorderHit.TopRight => HTTOPRIGHT,
            BorderHit.BottomLeft => HTBOTTOMLEFT,
            BorderHit.BottomRight => HTBOTTOMRIGHT,
            _ => 0,
        };

        if (hit != 0) { m.Result = (IntPtr)hit; return; }
    }

    base.WndProc(ref m);
}
```

```csharp
using System.Collections.Generic;
using System.Drawing;
using System.Linq;

namespace VibranceHud
{
    /// <summary>
    /// Keeps a restored window on a screen that still exists.
    ///
    /// The quick-vibrance popup already validates its saved position this way. The main
    /// window never saved one at all, so it opened dead-centre every launch. Restoring a
    /// position blindly is worse than not restoring it: a spot on a monitor that has since
    /// been unplugged strands the window somewhere the user cannot reach it.
    /// </summary>
    public static class WindowBounds
    {
        public static Rectangle ClampToVisible(Rectangle saved, IEnumerable<Rectangle> screens)
        {
            if (saved.IsEmpty || saved.Width <= 0 || saved.Height <= 0) return Rectangle.Empty;

            var list = screens.ToList();
            if (list.Count == 0) return Rectangle.Empty;

            // Never larger than the screen it will land on.
            var target = list.FirstOrDefault(s => s.IntersectsWith(saved));
            bool offScreen = target == default;
            if (offScreen) target = list[0];

            int w = System.Math.Min(saved.Width, target.Width);
            int h = System.Math.Min(saved.Height, target.Height);

            if (!offScreen && saved.Width <= target.Width && saved.Height <= target.Height)
                return saved;

            // Centre it on the target screen, keeping the size we just clamped.
            return new Rectangle(
                target.X + (target.Width - w) / 2,
                target.Y + (target.Height - h) / 2,
                w, h);
        }
    }
}
```

Create `ToneCurve.cs`:

```csharp
using System;

namespace VibranceHud
{
    /// <summary>
    /// Builds the 3x256 display gamma ramp from every tone control at once.
    ///
    /// This is the whole reason advanced colour is possible without DX11. The colour
    /// matrix in <see cref="ColorAdjust"/> is linear and cannot express highlights,
    /// shadows, fade or a split tone. The display's gamma ramp is a per-channel lookup
    /// table, so it can express any monotonic curve - and it already works on every GPU,
    /// which the DX11 path does not.
    ///
    /// <see cref="GammaCurve"/> was doing one power function and copying it to all three
    /// channels. This replaces that with the full grade, and reduces to exactly the old
    /// curve when only gamma is set.
    ///
    /// Pure maths, unit-tested without a display.
    /// </summary>
    public static class ToneCurve
    {
        public static ushort[] Build(ToneSettings t)
        {
            var ramp = new ushort[GammaCurve.Entries * 3];

            double gamma = Math.Clamp(t.Gamma, 50, 150) / 100.0;
            double invGamma = 1.0 / (gamma <= 0 ? 1 : gamma);

            // Endpoint remap. Blacks lifts or crushes the floor, whites the ceiling.
            double black = Math.Clamp(t.Blacks, -100, 100) / 100.0 * 0.25;
            double white = 1.0 + Math.Clamp(t.Whites, -100, 100) / 100.0 * 0.25;

            double fade = Math.Clamp(t.Fade, 0, 100) / 100.0 * 0.25;

            double hi = Math.Clamp(t.Highlights, -100, 100) / 100.0;
            double sh = Math.Clamp(t.Shadows, -100, 100) / 100.0;

            double tintS = Math.Clamp(t.ShadowTint, -100, 100) / 100.0 * 0.12;
            double tintM = Math.Clamp(t.MidtoneTint, -100, 100) / 100.0 * 0.12;
            double tintH = Math.Clamp(t.HighlightTint, -100, 100) / 100.0 * 0.12;

            for (int i = 0; i < GammaCurve.Entries; i++)
            {
                double x = i / (double)(GammaCurve.Entries - 1);

                // 1. Endpoints, before anything shapes the middle.
                double span = white - black;
                double v = span <= 0.0001 ? 0 : (x - black) / span;
                v = Math.Clamp(v, 0, 1);

                // 2. Gamma. Identical to GammaCurve.Build when nothing else is set.
                v = Math.Pow(v, invGamma);

                // 3. Region weights. Shadows bite hardest at black, highlights at white,
                //    midtones peak in the middle, and all three fall to zero at the ends
                //    they do not own - so one control never silently moves another's range.
                double wS = (1 - v) * (1 - v);
                double wH = v * v;
                double wM = 4 * v * (1 - v);

                v += sh * wS * 0.35;
                v += hi * wH * 0.35;
                v = Math.Clamp(v, 0, 1);

                // 4. Fade last, so the lifted black point survives everything above it.
                v = fade + v * (1 - fade);

                // 5. Split tone: warm pushes red up and blue down, cool the reverse,
                //    each weighted to its own tonal region.
                double tint = tintS * wS + tintM * wM + tintH * wH;

                ramp[i] = Q(v + tint);                                  // red
                ramp[GammaCurve.Entries + i] = Q(v);                    // green
                ramp[GammaCurve.Entries * 2 + i] = Q(v - tint);         // blue
            }

            EnforceMonotonic(ramp);
            return ramp;
        }

        private static ushort Q(double v) =>
            (ushort)Math.Clamp(Math.Round(Math.Clamp(v, 0, 1) * 65535.0), 0, 65535);

        /// <summary>
        /// A ramp that dips produces visible banding and posterisation, and an aggressive
        /// tint on a steep curve can dip. Clamping each entry to at least its predecessor
        /// costs nothing and makes the output safe for any combination of settings.
        /// </summary>
        private static void EnforceMonotonic(ushort[] ramp)
        {
            for (int c = 0; c < 3; c++)
            {
                int o = c * GammaCurve.Entries;
                for (int i = 1; i < GammaCurve.Entries; i++)
                    if (ramp[o + i] < ramp[o + i - 1]) ramp[o + i] = ramp[o + i - 1];
            }
        }
    }
}
```

```csharp
/// <summary>
/// Shell-level shortcuts.
///
/// ProcessCmdKey rather than KeyDown: these have to win over whatever child control has
/// focus, and Ctrl+Tab in particular is swallowed by the normal key path.
/// </summary>
protected override bool ProcessCmdKey(ref Message msg, Keys keyData)
{
    switch (keyData)
    {
        case Keys.Escape:
            SaveWindowBounds();
            Hide();
            return true;

        case Keys.Control | Keys.Tab:
            StepNav(forward: true);
            return true;

        case Keys.Control | Keys.Shift | Keys.Tab:
            StepNav(forward: false);
            return true;
    }

    // Ctrl+1..9 jumps straight to a tab, matching every browser and chat app.
    if ((keyData & Keys.Control) == Keys.Control)
    {
        int digit = (keyData & Keys.KeyCode) - Keys.D1;
        if (digit >= 0 && digit < 9)
        {
            var visible = VisibleNavButtons();
            if (digit < visible.Count) { visible[digit].PerformClick(); return true; }
        }
    }

    return base.ProcessCmdKey(ref msg, keyData);
}

private System.Collections.Generic.List<NavButton> VisibleNavButtons() =>
    new[] { _navVibrance, _navMonitor, _navGames, _navKeybinds, _navFps,
            _navCrosshair, _navSettings, _navEditor, _navAccount }
        .Where(b => b.Visible).ToList();

private void StepNav(bool forward)
{
    var visible = VisibleNavButtons();
    if (visible.Count == 0) return;

    int current = visible.FindIndex(b => b.Active);
    if (current < 0) current = 0;

    visible[NextNavIndex(current, visible.Count, forward)].PerformClick();
}
```

```csharp
using System;
using System.Runtime.InteropServices;

namespace VibranceHud
{
    /// <summary>
    /// How often to animate.
    ///
    /// The app ran a fixed 33ms tick, which is roughly 30fps. This app's users bought
    /// high-refresh monitors specifically so that motion is smooth, so 30fps animation is
    /// a detail they will notice faster than almost anyone else.
    /// </summary>
    public static class RefreshRate
    {
        [DllImport("user32.dll")] private static extern IntPtr MonitorFromWindow(IntPtr hwnd, uint flags);

        /// <summary>Milliseconds per frame for a given refresh rate, clamped to sane bounds.
        /// WinForms timers have roughly 15ms granularity, so this is a target rather than a
        /// guarantee - but asking for 6ms does get noticeably closer than asking for 33.</summary>
        public static int IntervalMs(int hz)
        {
            if (hz <= 0) return 33;
            return Math.Clamp((int)Math.Round(1000.0 / hz), 4, 33);
        }

        /// <summary>The refresh rate of the display the window is on, or 0 if unknown.</summary>
        public static int ForWindow(IntPtr hwnd)
        {
            try
            {
                var screen = System.Windows.Forms.Screen.FromHandle(hwnd);
                var mode = new DEVMODE { dmSize = (short)Marshal.SizeOf<DEVMODE>() };
                if (EnumDisplaySettings(screen.DeviceName, -1, ref mode))
                    return mode.dmDisplayFrequency;
            }
            catch { }
            return 0;
        }

        [DllImport("user32.dll", CharSet = CharSet.Ansi)]
        private static extern bool EnumDisplaySettings(string? deviceName, int modeNum, ref DEVMODE devMode);

        [StructLayout(LayoutKind.Sequential, CharSet = CharSet.Ansi)]
        private struct DEVMODE
        {
            [MarshalAs(UnmanagedType.ByValTStr, SizeConst = 32)] public string dmDeviceName;
            public short dmSpecVersion, dmDriverVersion, dmSize, dmDriverExtra;
            public int dmFields;
            public int dmPositionX, dmPositionY;
            public int dmDisplayOrientation, dmDisplayFixedOutput;
            public short dmColor, dmDuplex, dmYResolution, dmTTOption, dmCollate;
            [MarshalAs(UnmanagedType.ByValTStr, SizeConst = 32)] public string dmFormName;
            public short dmLogPixels;
            public int dmBitsPerPel, dmPelsWidth, dmPelsHeight, dmDisplayFlags, dmDisplayFrequency;
            public int dmICMMethod, dmICMIntent, dmMediaType, dmDitherType, dmReserved1, dmReserved2;
            public int dmPanningWidth, dmPanningHeight;
        }
    }
}
```

```csharp
using System.Drawing;
using System.Windows.Forms;

namespace VibranceHud.Share
{
    /// <summary>
    /// Grabs the desktop as it is *without* the colour effect.
    ///
    /// This looks like a limitation and is actually exactly what the share card needs. The
    /// Magnification path applies colour after composition, so CopyFromScreen never sees
    /// it - which means one capture gives us a clean "before", and applying the grade in
    /// software gives us an "after" that matches what the recipient will get from the code.
    /// Both halves come from the same pixels, so the comparison is honest.
    /// </summary>
    public static class ScreenGrab
    {
        public static Bitmap PrimaryDesktop()
        {
            var bounds = Screen.PrimaryScreen?.Bounds ?? new Rectangle(0, 0, 1920, 1080);
            var bmp = new Bitmap(bounds.Width, bounds.Height);
            using var g = Graphics.FromImage(bmp);
            g.CopyFromScreen(bounds.Location, Point.Empty, bounds.Size);
            return bmp;
        }
    }
}
```

- [ ] **Step 4: Implement the card**

Create `Share/ShareCard.cs`. Structure:

```csharp
public readonly record struct ShareCardOptions(int Width, int Height);
```

`Render(Bitmap before, ProfileCode code, ShareCardOptions o)`:

1. Create the output bitmap at `o.Width × o.Height`.
2. Draw `before` scaled to fill, into the left half (source-clipped, not squashed).
3. Build the after image: clone the source region, apply `ColorAdjust.Build(...)` via a `ColorMatrix` on an `ImageAttributes`, then apply the tone curve as a per-channel remap table built from `ToneCurve.Build(code.Tone)`. Draw into the right half.
4. Draw a 3px accent divider down the centre, with small `BEFORE` and `AFTER` labels.
5. Bottom band: the PlexusX logo from `BrandAssets.HorizontalLogo(false)`, and the code in a large monospace-ish bold face, plus one line of small text — `plexusx.app` — so the image carries where to get it.
6. Return the bitmap. Never mutate the input.

The gamma ramp becomes a GDI+ remap via `ImageAttributes.SetGamma` for the simple case, or by pre-applying the ramp per pixel for the full grade. Pre-applying per pixel with a lookup table is simplest and correct:

```csharp
// One lookup per channel, built straight from the ramp the display would get.
var ramp = ToneCurve.Build(code.Tone);
var lutR = new byte[256]; var lutG = new byte[256]; var lutB = new byte[256];
for (int i = 0; i < 256; i++)
{
    lutR[i] = (byte)(ramp[i] >> 8);
    lutG[i] = (byte)(ramp[GammaCurve.Entries + i] >> 8);
    lutB[i] = (byte)(ramp[GammaCurve.Entries * 2 + i] >> 8);
}
```

Then walk the after-bitmap's pixels with `LockBits` and map each channel through its LUT.

## Notes for whoever executes this

**The riskiest task is Task 2 and 3 (DPI).** It touches every page and "mostly converted" still
looks broken. Convert one page, verify it at 150%, commit, then move on. Do not batch them.

**Tasks 7 and 10 are pure maths and must be TDD'd strictly.** Colour maths that is subtly wrong
does not throw — it just makes everyone's screen slightly off and every shared code slightly
wrong. The tests are the specification.

**The pre-existing 841 tests are the safety net for the colour work.** `ProfileCodeTests`,
`ProfileCodeContrastTests` and the gamma tests exist precisely to catch a format or curve
regression. If one of them goes red, stop and understand why before changing it.

**Phase 4 can ship separately.** Phases 0-3 are a complete, sellable product on their own. If
time runs out, cut from the end of Phase 4, not the middle of Phase 0.
