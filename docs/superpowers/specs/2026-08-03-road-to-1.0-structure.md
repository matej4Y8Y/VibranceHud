# Road to 1.0 — what goes where, and what goes away

Written 2026-08-03, unattended session.

Brief was: everything in the right place, everything works with everything else, everything
makes sense. Two prompts were given as examples of the problem — *why is resolution buried in
the game hub when it could be its own Monitor tab*, and *nobody uses pre-launch profiles, or
profiles in general*. Both are symptoms of the same thing, so this starts there.

## The one problem underneath both

**Features were filed by which game they were built for, not by what they do.**

Resolution went into the Rust page because Rust's launcher needed it. That decision made a
display setting unreachable for CS2, Apex and Fortnite players, and findable by Rust players
only by accident. Nothing about resolution is Rust-specific.

The same mistake made the Profile Editor: per-game colour was built as its own page with its
own game dropdown, so colour now lives in two places that never talk to each other. You tune
your look on Display, then re-tune it from scratch in the editor if you want it to auto-apply.
Nobody does that twice.

The test for 1.0: **a feature belongs to the thing it changes, not to the game that motivated
it.**

## Scenarios that expose it

Walked through as real sessions rather than feature lists.

**"I just want Rust to look better."** Opens app → Display → drags saturation → done. This is
the overwhelming majority of all use. Everything else is a detour. It works today.

**"I play CS2 and want 1280x960 stretched."** Today: goes to Game → CS2 → no resolution
anywhere → gives up and opens the NVIDIA panel. This is the reported gap. Fixed by the
Monitor tab.

**"I want my colours back when I alt-tab to Discord."** Works today, and is invisible, which
is correct.

**"I set up Rust colours, now I'm playing CS2."** Today: Display is global, so CS2 gets Rust's
look. To change it they either drag sliders again or discover the Profile Editor and configure
the same values a second time. **This is the actual hole, and profiles were the wrong shape of
answer to it.**

**"I reinstalled Windows."** Everything is in one settings.json. Fine — but nothing exports
it. Profile codes exist for colour only.

## Decisions taken this session

### 1. Monitor is a tab (done)

Resolution now has its own tab beside Display, because Display is *what colour the picture is*
and Monitor is *what shape it is*. Same subject, same place in the nav.

It carries two things:

- **Right now** — switch the desktop immediately. This is the "stop making me open the NVIDIA
  panel" job, and it only counts if it is one click from anywhere.
- **When a game launches** — a per-game rule, applied on launch, undone on exit.

The launch rule moved out of the Rust page into `AppSettings.MonitorRules`, and the profile
coordinator applies it for every game.

**A real bug was fixed on the way.** The launch handler looked up the colour profile first and
returned early when there wasn't one. Since most people have no profile, the resolution switch
was being skipped entirely for them. Resolution is now applied before the gate and independent
of it — they are two features that happen to share a trigger, not one feature.

Existing Rust resolution choices migrate automatically, so nobody's setup stops working.

### 2. Process names centralised (done)

`RustClient`, `cs2`, `r5apex`, `FortniteClient-Win64-Shipping` were written out in six places.
They live on `SupportedGame` now. Adding a game is one catalogue entry instead of an edit in
the watcher plus one per service.

### 3. Profiles — the recommendation

**Do not keep the Profile Editor as a tab.** It is the only page in the app that duplicates
another page's controls, and duplication is why nobody uses it: to get a per-game look you must
configure it twice, in two places, from two different starting points.

But the *capability* is right — "CS2 should look different to Rust" is a real want, and the
auto-apply machinery already works. The problem is purely how you reach it.

**Proposed replacement: one button on Display.**

> **Save this look for Rust**   (button appears when a game is selected in the chooser)

That is the whole feature. Your live look becomes that game's profile, applied when it
launches, restored when it closes. And underneath it, one line: *"Rust: saturation 140,
contrast 106 — saved yesterday. Forget this."*

Why this is strictly better:

- Nothing to configure twice. What you see is what gets saved.
- Discoverable — it is on the page people already live on.
- Removes a tab, a page, and a whole duplicate set of sliders.
- The chooser already tells the app which game you mean, so there is no picker to build.

Not implemented in this session: it deletes a working feature and changes what auto-apply does
to people's screens, which is not something to ship unattended. It is the single highest-value
cleanup left.

### 4. Nav after the change

```
Display        colour                    ← where everyone lives
Monitor        resolution, refresh       ← new
Crosshair      overlay
Game           the selected game's own settings + launch
FPS Tweaks     system tweaks
Settings
Account
```

Seven items, each answering a different question, none overlapping. Profile Editor's row is
freed by folding it into Display.

## What 1.0 still needs

Ordered by what actually blocks a public launch.

**Blocking**
1. **EV code-signing certificate.** The launch plan already calls the SmartScreen warning the
   number one conversion killer. Nothing else matters as much.
2. **One price, everywhere.** Discord says €3/mo and €8–12 lifetime; the site says $4 and $12.
3. **Fix the GPU claim on the site.** Saturation is any GPU; vibrance is NVIDIA only.
4. **Legal pages** linked from the installer, not buried in About.
5. **Clean-machine install test.** No .NET, no dev tools, no prior PlexusX.

**Correctness, unverified by anyone**
6. Biome presets in an actual game.
7. AMD/Intel — software vibrance path has never been confirmed by a second person.
8. Multi-monitor DVC.
9. Laptop hybrid graphics.

**Product**
10. Fold the Profile Editor into Display (§3).
11. Per-section reset. Getting back to neutral currently means dragging four sliders.
12. Named custom presets — people will tune a look and want it back.
13. Profile codes should carry contrast and temperature; they predate both.
14. Empty states that say what to check.

**Then the remaining programme**
15. Launcher: pre-launch actions in one place, undone on exit.
16. Keybinds page — biggest build, needs a per-game command catalogue, legitimate binds only.

## Rejected

- **Scoping Display per game.** Considered and dropped: the home page must have one unambiguous
  meaning, and "these sliders sometimes mean your desktop and sometimes mean Rust" is not it.
- **Tying auto-apply to the chooser.** Picking a game from a menu must not change what is on
  your monitor. Auto-apply keys off what actually launches; the chooser is a UI selection.
- **Exploit binds** (`gc.collect` levitation and similar). Contradicts the product's own stated
  line, gets users banned, and would put PlexusX on cheat lists — which kills the legitimate
  95% of the keybinds feature along with it.
