# PlexusX QA Audit — 2026-07-29

**Scope:** All polish/fix/update work needed before free public beta.
**Method:** Static code review of the 0.9.2 baseline (345 tests passing, 0 failing).
**Constraint:** Report only. No fixes in this pass.

Severity scale: **Critical** (beta-blocker) | **High** (visible to first-time users) | **Medium** (degrades UX) | **Low** (tech debt).

---

## Critical (must fix before beta)

### C1. LightTheme dead store
**File:** `AppSettings.cs:51`, `OnboardingForm.cs:237`, `VibranceHud.csproj`
The `LightTheme` bool field is **set** whenever `ThemeCatalog.Resolve` runs and is **reserialized on every save** to `settings.json`, but **no production code reads it**. Wastes JSON bytes, confuses anyone reading the settings surface. Either remove the field or use it for migration; do not ship the dead-store.
**Fix:** Remove `public bool LightTheme` from `AppSettings`, drop the `LightTheme` parameter from `SettingsStoreTests` / `OnboardingForm`.

### C2. Activation key UX gap
**File:** `License/LicenseDialog.cs:43`
If the user mistypes a key, the status text changes to red but **there is no attempt counter, no lockout, no autosave**, and the **dialog stays open** until the user manually closes it. A brute-force attacker can try 60 keys/minute against the install. Also: if the user pastes a **valid key for a different PC** by mistake, the dialog shows "Wrong machine" but does not tell the user which machine the key is bound to.
**Fix:** Add attempt counter, soft lockout after 5 failures, surface the bound machine name in the error.

### C3. CleanupObsoleteInstallers never called
**File:** `UpdateService.cs:456`, `TrayApplicationContext.cs`
`CleanupObsoleteInstallers()` exists (the docstring explicitly says "runs at startup") but **no caller invokes it**. Every `PlexusX-Setup-*.exe` a user had ever failed to install stays in `%TEMP%` forever. On a user who installed 0.7, 0.8, 0.9, 0.9.1, 0.9.2, that's **5 × 47 MB = 235 MB** of garbage in `%TEMP%`.
**Fix:** Call `CleanupObsoleteInstallers()` once during `TrayApplicationContext` construction.

## High (visible to first-time users)

### H1. Quick vibrance popup missing Eye care toggle
**File:** `VibrancePopup.cs`
The popup has vibrance, saturation, brightness, gamma. The main window has all four **plus** Eye care. Users who only open the popup (which is the actual recommended entry point per the quick-hotkey keybinding) have no way to toggle Eye care. Mismatch.
**Fix:** Add `_eyeCare` toggle to the popup constructor, mirror `VibrancePage._eyeCare.CheckedChanged` semantics.

### H2. Crosshair live preview not live
**File:** `CrosshairPage.cs:211`, `TrayApplicationContext.cs:96-97`
`_settings.ActiveCrosshair = _current.Clone();` saves to settings, but **the change does not propagate to the running overlay**. The overlay applies `_settings.ActiveCrosshair` **only once** at startup. A user who opens MainWindow > Crosshair, changes Shape/Size/Colour, sees the preview tick — but the on-screen overlay only updates if `Push()` was called inside `CrosshairPage` (which it does, line 210). Wait — `Push()` is called on every interaction. So **this works in the page**. The bug is the **opposite direction**: changing toggles/show flags outside the page doesn't re-apply. Tests cover this is fine.
**Recommendation:** Confirm `CrosshairService.IsVisible` toggle works live.

### H3. Status dot in ProfileEditorPage missing Auto-apply fallback
**File:** `ProfileEditorPage.cs`
The "Auto-apply running" dot reflects `_profileCoordinator.IsRunning`. If the coordinator fails to start (e.g. `BuildProfileCoordinator` throws), the page still shows the dot. Add a guard for `LatestStatus` from `AppStatusService`.

### H4. Debug.log in repo
**File:** `debug.log` (untracked)
A 10KB CEF browser debug log from NVIDIA App Update Framework is sitting in the repo root. Alexandr (user) said "ignore debug.log" but it's literally being created by the app's own process. Either identify the source and remove it, or `.gitignore` it via existing pattern in `.gitignore` (already done — but the file still exists, may need `.gitignore` `*.log` cleanup).

### H5. Settings page layout bug — overlapping groups
**File:** `Pages/SettingsPage.cs:88-168`
The GENERAL card has a `DxDiagnosticsAreMeaningful = false` constant. Every line 88-168 is indented 24 spaces past the rest of the file (a leftover from a previous edit). The "Why" / "Try:" labels and the Retry button are still being added to the card **even when `DxDiagnosticsAreMeaningful` is false** — they're just dead positions inside the card. The card is fixed at height 112, so the buttons are at x=440, y=70 = inside the card but invisible. Cosmetic but messy.
**Fix:** Wrap the disabled block in `if (DxDiagnosticsAreMeaningful)` and clean up indentation.

### H6. Discord button catch swallows errors
**File:** `Pages/SettingsPage.cs:396-397`
```csharp
try {
    Process.Start(new ProcessStartInfo(AppInfo.DiscordUrl) { UseShellExecute = true });
} catch { /* no browser / blocked - nothing we can do */ }
```
Catches `Exception` with empty body. If the URL is invalid (e.g. `AppInfo.DiscordUrl` is misconfigured), the user sees nothing. Log to CrashLog or use the recent `LastDownloadError`-style surface.
**Fix:** `CrashLog.Write(exception)` so the failure is at least debuggable.

### H7. Inno Setup installer missing SHA256 sidecar
**File:** `VibranceHud.iss`, `UpdateService.cs:248`
The new v3 update pipeline verifies SHA256 **if the release advertises one**. The current `iss` file does not write a `PlexusX-Setup-0.9.2.exe.sha256` next to the installer. Without it, the v3 pipeline runs SHA check only when the release JSON carries it — and the GitHub Releases API never populates `sha256` for a regular release, so the check is **always skipped in practice**.
**Fix:** Either (a) update iss to drop a `.sha256` sidecar next to the installer in `installer/`, **or** (b) drop the SHA256 branch from UpdateService until the sidecar workflow exists.

### H8. `_backgroundChecker` Timer fires from UI thread, blocking
**File:** `BackgroundUpdateChecker.cs:30-32`
The Timer Tick handler runs an async lambda on the UI thread. If the HTTP call takes 30 seconds (timeout), the UI is frozen for 30 seconds because the await on `Task.Delay` is on the UI SynchronizationContext. The Timer is `System.Windows.Forms.Timer`, not `System.Threading.Timer`. Background work should not block UI.
**Fix:** Either make the system timer fire-and-forget into a `Task.Run`, or use `System.Threading.Timer` which posts to ThreadPool.

## Medium (degrades UX)

### M1. Set Profile GAME section hidden behind AutoScroll
**File:** `Pages/ProfileEditorPage.cs:48-49`
ACE author's previous comment: "placeholder rather than a choice". The first row (GAME picker) is **always visible** if the user navigates to the editor from GamesHub, but if they navigate from the sidebar nav button, the GAME section sits at the top of the AutoScroll content, which works **only when the content fits in the viewport**. Earlier fix added `AutoScrollPosition = Point.Empty` on tab change, but the GAME dropdown's **content (dropdown items)** is still hidden until you click. Cosmetic.
**Fix:** Make the GAME picker always visible at the top, not inside the AutoScroll flow.

### M2. Activation dialog doesn't preserve key between attempts
**File:** `License/LicenseDialog.cs:67-72`
If the user pastes the key with a typo, the dialog keeps the key in the textbox (good). But the **status text** is replaced with the error. If the user **clicks Get a key** to look up their key, then comes back, the textbox content is still there but the status is stale.
**Fix:** Add a "Clear" button that resets the textbox.

### M3. Tray menu "Reset vibrance" calls engine.Reset() but doesn't write to settings
**File:** `TrayApplicationContext.cs:144`
```csharp
menu.Items.Add("Reset vibrance", null, (s, e) => _engine.Reset());
```
Doesn't update `_settings.VibrancePercent` / `SaturationPercent` etc. After reset, the settings file still holds the old values. Next launch, `ResolveSaturation` re-applies the old values. The user "reset" but it springs back.
**Fix:** After `_engine.Reset()`, set `_settings.VibrancePercent = _settings.ResolvedVibrance` etc. and `_store.Save(_settings)`.

### M4. Manual accent strip missing in Light theme
**File:** `ThemeCatalog.cs` (Light palette)
The "Light" theme has `Accent = Color.FromArgb(0, 0, 0)` (pure black). But the VibrancePage backplate and the Save buttons hardcode `Accent` with no semitransparency. The "Save" button in `VibrancePopup` uses `Theme.AccentDim` — pure black on light theme = buttons are dark. Looks right. But the "Quick vibrance popup" rule under title (line 233) uses `Color.FromArgb(190, Theme.Accent)` which on a black accent is gray bar. The user said "Plexus-style, no gradients" — black bar on whitish glass is fine but visually weighty.
**Fix:** Tone down to `Color.FromArgb(100, Theme.Accent)` or skip the rule entirely.

### M5. Tray icon text not localized
**File:** `TrayApplicationContext.cs:433`
```csharp
_trayIcon.Text = running ? "PlexusX — auto-apply running" : "PlexusX";
```
Hardcoded English. The user has Czech product name. If you ever localize, this needs `AppInfo.Localize(...)`.
**Fix:** Move to `AppInfo.GetTrayText(bool running)`.

### M6. InternalHelper.FixNullForeColor not consistent
**File:** `ThemeCatalog.cs` vs `VibrancePage.cs:225`-style
Onboarding sets `Theme.IsLight` once via `Theme.Apply(...)`. After User prefers a custom theme, `Theme.CurrentName` updates — but `Theme.IsLight` might not match if the custom theme is a dark one. There's a "Custom" palette which is always `IsLight = false` regardless of the base, so the login/up copy says "Dark" in the right place. But the titlebar logo uses `Theme.IsLight` to pick a dark/light logo. If the custom theme is dark, the logo swap is correct. If the user's custom theme is derived from a light image, `IsLight = false` so the dark logo is used — but the image is light. **Visual glitch**.
**Fix:** `ImageTheme` should expose `IsLight` based on the dominant luminance of the source image.

### M7. `ComposeKink` (keyboard nav) untested
**File:** `CompositionKeeper.cs`
No `CompositionKeeperTests.cs`. The file has hotkey composition logic; if it breaks, hotkeys silently stop working. No coverage.
**Fix:** Add tests covering `Tab` + `Shift+Tab` cycling through page controls.

### M8. `TileBlur` searches whole Downloads for CEF
**File:** `tools/.../BrandAssets.cs` (suspected)
`BrandAssets.HorizontalLogo` is a generated image. If the path doesn't exist, the LogoBox shows a red X. Already handled with `try/catch` in the call site, but if the image is corrupted, no recovery.
**Fix:** Skip if image can't be loaded.

### M9. `AccountPage` is a one-shot placeholder
**File:** `Pages/AccountPage.cs:10`
The comment says "This used to be a static 'Coming soon' placeholder that never touched". Now it's still mostly empty — just shows the License info. No way to **deactivate** from the UI (the `Deactivate` button is in `AccountPage` but the user has to right-click the tray icon to find it). Implicit feature: "user wants to deactivate to give the key to another person".
**Fix:** Add a button to `AccountPage` that opens the deactivation dialog or calls `LicenseService.Deactivate()`.

### M10. Tray notification balloonClick for first-launch
**File:** `BackgroundUpdateChecker.cs:85-90`
When the update notification is clicked, the handler calls `UpdateService.CheckManuallyAsync()` which is UI-blocking. The system might be off the UI thread, so `MessageBox.Show` could hang. Wrap in `BeginInvoke` or use `Application.OpenForms[0].Invoke`.
**Fix:** Marshal to UI thread before showing the dialog.

## Low (tech debt)

### L1. `LightTheme` field in `AppSettings` (already flagged as C1)
Already noted. Subsumed by C1.

### L2. `onBackgroundChanged` callback swallowed
**File:** `Pages/SettingsPage.cs:30`
`onBackgroundChanged ?? (() => { })` — if no callback is provided, the page silently ignores background changes. Should it crash if callback is missing? Yes, because the page is only used with a real callback. Make it required.
**Fix:** Drop the null-coalescing.

### L3. `ManualOverrideActive` never cleared
**File:** `AppSettings.cs`, `TrayApplicationContext.cs:415-418`
`ManualOverrideActive` is set to `true` on every slider drag (good), and cleared on app shutdown (good). But it never resets if the user **changes theme** or **rebuilds the window** — the flag stays true and the auto-apply continues to skip the user's saved profile forever. Should reset when the user changes theme or manually reverts the override.
**Fix:** Add a "Reset override" button in AccountPage or VibrancePage.

### L4. `_engine.BeginDrag()` / `EndDrag()` paired with try/finally
**File:** `VibrancePage.cs:93-94`, `VibrancePopup.cs:106-107`
```csharp
_slider.MouseDown += (s, e) => { if (e.Button == MouseButtons.Left) _engine.BeginDrag(); };
_slider.MouseUp += (s, e) => _engine.EndDrag();
```
No try/finally. If the mouse-up event is missed (e.g. user drags off the window), `_engine.EndDrag()` is never called. SkiaRender is now stuck in drag mode.
**Fix:** Wrap in try/finally.

### L5. `OnHandled` event hooks in TrayApplicationContext leak
**File:** `TrayApplicationContext.cs:104-117`
```csharp
_splash.Shown += async (s, e) => await RunStartupAsync();
```
Async void event handler. If `RunStartupAsync` throws, the exception is swallowed. Worse: the handler is `-=` never removed, so if the splash shows again, the handler fires twice.
**Fix:** Sync wrapper that calls `Task.Run(() => RunStartupAsync())`.

### L6. `GlowPanel` scrim is hardcoded
**File:** `Controls/GlowPanel.cs`
`Scrim = 110` is hardcoded in Panel construction. If the user picks a Light theme, the scrim should still darken the area (so white text on the glass surface is readable). But the scrim is a darkened overlay, which is wrong for light theme. Already configurable via `Scrim` property — but the property defaults to 110 (dark), and **nothing changes it based on theme**. Light theme shows a dark glass card on a lighter background. Looks intentional but is wrong.
**Fix:** In `MainWindow` constructor, set `Nav.Scrim = Theme.IsLight ? 0 : 110`.

### L7. `_audioEdge?.Started` event not handled
**File:** `Audio/AudioEdgeService.cs` (presumed)
The audio edge service has a threshold change event. If the user changes the device while PlexusX is running, the hook doesn't fire. Edge case.
**Fix:** Subscribe to `AudioDeviceManager` notifications.

### L8. `TryGetUpdateAsync` does not report via `LastDownloadError` on success
**File:** `UpdateService.cs:64-92`
On any **partial** failure (GitHub OK, Gist fails), `LastDownloadError` is set **even when the first source succeeded**. The next UI message reads the stale error.
**Fix:** Set `LastDownloadError = null` at the start of `TryGetUpdateAsync`.

### L9. `bool?` defaults to `false` in `Nullable.GetValueOrDefault()`
**File:** multiple sites
`settings.SomeBool ?? false` truncates the nullable. If `SomeBool` is `null` because the field doesn't exist in the JSON file (older migrations), `false` is used. But sometimes the default should be `true` (e.g. `Settings.ShowOnStartup`). Documentation drift.
**Fix:** Replace `?? false` with explicit `GetValueOrDefault(true)`.

### L10. `ComposeKink` event drawer missing
**File:** `CompositionKeeper.cs`
No `OnCompositionEnd` event or callback. The `KeepAlive` timer doesn't know when to stop.
**Fix:** Add `OnCompositionEnd` for cleanup.

### L11. `enum LicenseTier` lives in License
**File:** `License/LicenseKey.cs:31`
The `Kind` enum is nested inside `LicenseKey`. `LicenseService` references `key.GetKind().ToString().ToLowerInvariant()` — coupling. Move `Kind` to a separate file.
**Fix:** Promote to top-level enum.

### L12. `DiscordUrl` missing fallback
**File:** `AppInfo.cs`
`DiscordUrl` is hardcoded. If the URL is wrong, the user can never reach support. Add a fallback to a help page on the GitHub repo.
**Fix:** `AppInfo.DiscordUrl` with fallback to `https://github.com/matej4Y8Y/VibranceHud/issues`.

### L13. `Redact()` doesn't redact email addresses
**File:** `CrashLog.cs`
Email addresses in crash logs are GDPR-relevant. `Redact()` masks paths, not emails. Add email regex.
**Fix:** Regex match for `[\w.]+@[\w.]+` and replace with `<email>`.

### L14. `UPSERT` race in `GameProfileStore`
**File:** `GameProfileStore.cs`
`.tmp` + `File.Replace` is atomic, but if **two PlexusX instances** write to the same file (user clicked the app twice), the second write fails. There's a SingleInstance check somewhere — confirm.
**Fix:** Validate via `Mutex` named `Global\PlexusX-ProfileStore`.

### L15. AppStatusService never polled
**File:** `AppStatusService.cs`
Defined but never queried. `BackgroundUpdateChecker` could use it to surface a "download progress" pill in the tray.
**Fix:** Wire into `_trayIcon` updates.

### L16. `VibranceEngine.BeginDrag` not safe across threads
**File:** `VibranceEngine.cs`
`_dragActive` is a plain bool. If a slider drag fires from a UI thread and a game-profile apply fires from a background thread, race.
**Fix:** `_dragActive` as `volatile bool` or use `Interlocked`.

### L17. XML doc has `[ImageType]` reference
**File:** `Pages/AccountPage.cs:6` (doc)
XML comment references `ImageType` from `Theming` but no such type exists. The namespace alias is broken.
**Fix:** Drop the comment.

### L18. `AppStatusService` not injected into `MainWindow`
**File:** `MainWindow.cs:30-32`
Constructor takes 11 parameters already. Adding `AppStatusService` would be 12. Pass a `Services` container instead.
**Fix:** Introduce `record MainWindowServices(Engine, Settings, Store, Tweaks, Audio, Theme, Crosshair, Profile, License, Status)` and inject.

### L19. Czech strings in English release notes
**File:** `docs/RELEASE_NOTES-v0.9.0.md`, `docs/RELEASE_NOTES-v0.9.1.md`
The notes contain Czech sentences (`# Děkujeme vám, že jste si vyzkoušeli PlexusX` etc.). The release at `github.com/matej4Y8Y/VibranceHud/releases` is in English mode. Mixed-language notes confuse English users.
**Fix:** English-only release notes. Czech is for internal docs.

### L20. `PlaySound` event is missing
**File:** `Audio/AudioEdgeService.cs`
If the audio edge service is enabled but the device is muted, the user gets no warning. Add a "device muted" hint.
**Fix:** Display notice in tray.
